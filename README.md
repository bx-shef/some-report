# some-report — Аналитика по лидам

> Last reviewed: 2026-09-02

Приложение Битрикс24: отчёт о пути лида от поступления до закрытия сделки. Встраивается в раздел
**CRM-аналитика** портала и открывается там же, где штатные отчёты. Nuxt 4 (SSG), данные только
читает.

> **Статус:** каркас собран, формулы посчитаны и покрыты тестами, интерфейс собирается.
> Данные пока **демонстрационные** — набор с согласованного макета. Живая выборка из портала
> подключается следующим шагом.

## Что показывает

1. **Сводка** — лиды, брак, квалифицировано, успешные сделки, конверсии, выручка.
2. **Воронка** — Лиды → Квалифицировано → Успешные сделки.
3. **Брак лидов по причинам** — кольцевая диаграмма и таблица.
4. **Причины проигрыша сделок** — количество и потерянная выручка по каждой.
5. **Эффективность источников** — по каждому источнику лиды, брак, конверсии, выручка; топ-5.
6. **Обработка лидов и потери до сделки** — обработано, просрочено, среднее время первого ответа.

## ⚠ Главное, что нужно знать про числа

ТЗ и согласованный макет считают конверсии по РАЗНЫМ знаменателям и дают на одних и тех же данных
разный результат:

| | Знаменатель | Лид → сделка | Лид → продажа |
|---|---|---|---|
| ТЗ | лиды без брака (1 000) | **100 %** | **62 %** |
| Макет | все лиды (1 250) | **80 %** | **49,6 %** |

Пока решение не принято, в отчёте стоит **переключатель** «Конверсии считать от: Качественные
лиды / Все лиды» — разница видна на месте, а не в переписке. Разбор и рекомендация —
[`docs/METRICS.md`](docs/METRICS.md).

## ⚠ Два блока ТЗ на портале пока не посчитать

Замер живого портала показал: причин брака лида и причин проигрыша сделки в Битрикс24 **нет ни
полем, ни справочником** — стадия брака одна, пользовательских полей ноль. Пока администратор
портала не заведёт стадии или поле-список, эти два блока покажут по одной строке. Что именно
завести и какой вариант лучше — [`docs/PORTAL.md`](docs/PORTAL.md).

## Быстрый старт

```bash
corepack enable && pnpm install
pnpm dev            # http://localhost:3000
```

Страницы приложения (`/app`, `/install`) вне портала Битрикс24 закрыты заглушкой — открывайте их с
`?preview=1`. Это штатный обход для разработки, скриншотов и тестов.

## Требования

- **Node.js 22 LTS**
- **pnpm** (через corepack; версия закреплена в `packageManager` в `package.json`)

## Команды

```bash
pnpm lint         # ESLint
pnpm typecheck    # два прохода: приложение + тесты
pnpm test         # Vitest (unit + nuxt)
pnpm check        # всё сразу — это же гоняет CI
pnpm generate     # сборка статики → .output/public
```

Перед пушем прогоняйте `pnpm check`.
